How I used AI

Across the project my workflow was consistently Level 2 — I instructed, AI built. I chose the architecture, picked the libraries, defined the contracts (SAM templates, function signatures, data shapes), and then directed the AI step-by-step to implement them. I reviewed every diff, ran tests where they existed, and verified deployments end-to-end against the assignment spec and rubric. The AI accelerated typing and boilerplate; the design decisions, debugging strategy, and "why" remained mine.

The decisions I made independently and then asked the AI to implement include: choosing CQRS (AWS writes, Azure reads) over a single-cloud database; forcing CPU-only PyTorch to fit the Lambda container size limit; using EventBridge instead of direct S3 → Lambda triggers; aggregating video frame tags by MAX-per-species rather than SUM; using a sentinel filter policy to make SNS "unsubscribe-all" idempotent against email-client link prefetchers; and per-user (rather than global) SHA-256 deduplication.

Notable AI mistakes / limitations

What I had to fix or override

  • Edge cases missed on the happy path. The most common failure mode was AI-generated code that worked for the obvious case but broke on real data. Concrete examples I caught and fixed:
    • Initial Tagger record shape didn't match the DynamoDB contract — found by integration test, fixed in 8ce5cbd.
    • Tagger merge logic was overwriting the presigned-upload's seed record instead of updating it — fixed by switching to update_item with a merge expression (5aba3bf).
    • Delete handler initially only granted S3 access to the uploads bucket; thumbnails were left orphaned in the separate bucket — fixed in ec7bd05.
    • SNS "unsubscribe-from-all" was tearing down the subscription, which forced a fresh confirmation email on resubscribe — Gmail's link prefetcher then silently auto-unsubscribed the user. I caught this by trying to resubscribe and getting an unsubscribe confirmation email. Reworked to park the FilterPolicy on a sentinel value (commit ceaaef7).
    • Search-by-thumbnail UI rendered a video's poster thumbnail via an <img> tag, breaking when the underlying file was an MP4. Fixed by returning file_type from the backend and branching on it in the React component.
  • Over-engineering tendency. Several early AI suggestions added abstractions I didn't need (factory wrappers around boto3 clients, multi-class state machines for simple polling). I pushed back on these and kept implementations flat where complexity wasn't justified.
  • Container size / Lambda limit awareness. The AI did not anticipate that the default PyTorch wheel pulls 6.8 GB of CUDA libraries — I diagnosed the size overrun by running du -sh on the Docker image layers, then directed the fix to install torch+cpu from the dedicated index URL (40d8b43).
